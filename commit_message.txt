⚡ Bolt: Replace O(N) array find with O(1) Map lookup in boutResolver

💡 What:
Replaced the `KIMARITE_REGISTRY.find((k) => k.id === result.kimarite)` call in `src/engine/bout/boutResolver.ts` with `getKimarite(result.kimarite)`.
Updated the import to `import { getKimarite } from "../kimarite";` instead of `KIMARITE_REGISTRY`.
Added a comment explaining the performance rationale and restored the original domain-context comment.

🎯 Why:
The previous implementation performed an `O(N)` array search over the `KIMARITE_REGISTRY` (which contains dozens of techniques) for every single bout resolved. This is a hot path operation, and since a basho involves simulating hundreds of bouts, these operations add up and increase tournament simulation latency.

📊 Impact:
Reduces kimarite lookup complexity from O(N) to O(1) per bout resolution. Across an entire tournament, this saves thousands of unnecessary array iterations, marginally improving overall tournament simulation speed and reducing CPU usage in the hot path.

🔬 Measurement:
The optimization can be verified by running `npx vitest run src/tests/unit/engine/bout/boutResolver.test.ts`. Functionality remains unchanged, but the engine now leverages the pre-computed `KIMARITE_MAP` via the `getKimarite()` helper function.
