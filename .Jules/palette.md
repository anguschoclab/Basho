## 2024-06-20 - Icon-Only Button Accessibility and Affordance
**Learning:** The project's custom `Button` component (`src/components/ui/button.tsx`) natively supports `tooltip` and `tooltipSide` props which wrap the component in a Radix tooltip. Additionally, `size="icon"` buttons should always include an `aria-label` for screen reader accessibility alongside the `tooltip` for visual affordance. Using the native `title` attribute is insufficient.
**Action:** Always verify that `variant="ghost" size="icon"` buttons (and similar icon buttons) use the built-in `tooltip` prop instead of native `title` attributes or manual TooltipWraps, and ensure a corresponding `aria-label` is present.
## 2024-06-27 - Disabled Button Tooltips Provide Essential Affordance
**Learning:** When `<Button>` components are disabled dynamically (e.g., due to insufficient funds, missing selections, or unmet prerequisites), standard visual styling (greyed out) doesn't tell the user *why* it's disabled. Native `disabled` attributes block pointer events, but Shadcn/Radix tooltips handle disabled triggers correctly if wrap configurations are set up. Using the custom `tooltip` and `tooltipSide` props conditionally based on the disabled state (e.g., `{...(!canAfford ? { tooltip: "Insufficient funds" } : {})}`) dramatically improves accessibility and reduces user friction without cluttering the UI with error text.
**Action:** When creating or modifying forms, panels, or widgets with conditionally disabled buttons, proactively include a `tooltip` explaining the prerequisite condition so users know how to unblock themselves.
