Local measurement on clean main (Apple Silicon, `bun scripts/bench-pipelines.ts`):
S1 p50=9.3ms · S2 p50=356.3ms · **S3_year p50=1464.3ms/p99=1798.8ms** · S4_25yr p50=1481.8ms.

S3 p50 delta vs committed baseline: **+9.3%** — under the 15% gate threshold; S3 p99 is *below* baseline p99. Yet all 15 open PRs show perf-gate FAIL at ~+42% (S3 p50 ≈1902ms) including doc-only PRs (#1127, #1133).

**Classification: NOT a real engine regression.** A true +42% pipeline degradation would reproduce locally; +9.3% is consistent with modest drift since Oct 8 plus hardware-class difference. The uniform +42% across all 15 PRs (including docs-only changes) indicates CI-side environment/runner drift vs the stale Oct-8 baseline. Mechanism: `perf-gate.yml` re-seeds baseline on main only `if: success()` — with a stale baseline every run fails, so the baseline can never self-heal (circular failure).

**Disposition:** gate repair — change the baseline-update step to run `always()` on main/develop so the baseline rolls forward on every main push (re-seed remains CI's job on main per convention; PRs keep their 15% gate against a fresh baseline). No T5 perf pin needed (no code regression to pin).
