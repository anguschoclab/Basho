### ❌ Disproved — six defects found, ALL in the test spec (zero in product code)

1. **`pub.id` field defect** (as originally found): `TalentCandidate` has `candidateId`/`personId`, no `id` — `fx.candidateId`/`fx.candidatePool` were always null → section 5 never executed before this work. **Fixed** (`pub.candidateId`).
2. **Silent section skips**: `if (fx.staffName)` / `if (fx.candidateId && …)` guards made skipped sections indistinguishable from passing ones. **Fixed** — hard `expect(…).toBeTruthy()` gates at fixture stage.
3. **Fresh worlds have zero staff**: `WorldFactory` creates `staff: new Map()` — staff only exists via `HIRE_STAFF`/NPC hiring, so the strengthened assertion failed loudly. **Fixed** — the spec dispatches `HIRE_STAFF` through `window.__BASHO_STORE__` → canonical worker path (`commands/economy.ts` → `staffService.hireStaff` → `resolveImpacts` → `syncAndDigest`).
4. **Fresh worlds have zero candidates**: `tickWeekTalentPool` only calls `refreshAllPools` when `dayIndex > 0 && dayIndex % 14 === 0` (`TalentPoolMaintenance.ts:23`); a day-0 world's pools are entirely empty. **Fixed** — the spec issues `TICK_MULTIPLE_DAYS` (days:7, retried ≤10× with `RESUME_SIM` + `RESOLVE_LOOP_DECISION` for `shouldHaltAdvance` breaks) until pools populate. _Caveat learned:_ `sendCommand` drops all non-tick commands while `pendingTick` is set (`gameStore.ts:171-179`) — dispatches must be serialized with `pendingTick` waits.
5. **No searchable prospect is canonically reachable in a fresh world** (the deepest find): at the day-14 refresh the emergency demographic floor dumps ~800 prospects into visible lists; domestic candidates are signed + materialized inside the same weekly tick; observed end state `{"high_school":{h:0,v:0},"university":{h:0,v:0},"foreign":{h:0,v:~145}}`. The only survivors are foreign — and `listVisibleCandidates` gates foreign behind `regionalPresence[originRegion] ≥ 40` (`talentPoolReads.ts:32-44`), which a new heya has none of. **Fixed** — the spec grafts a _real generated candidate_ (public band, sole membership in `high_school.candidatesVisible`, stripped from its source pool to satisfy the SerializationService cross-pool integrity check) via `useGameStore.onWorldUpdated` (the worker→context sync bridge that `syncWorld` itself invokes) + `LOAD_WORLD` for worker parity. This exercises the real search projection + deep-link rather than the recruitment lifecycle.
6. **Rival fixture could select a scouted rival**: after ~2 weeks of ticks, `playerKnowledge.scouting` legitimately covers some rival heyas, so `archetypeLabel` is _correctly_ rendered (observed "OshimanurturerDewanoumi" — not a leak, correct WS7 behavior). **Fixed** — the fixture now picks an explicitly _unscouted_ rival (mirrors `hasScoutingCoverage`).

Also learned: `page.goto` performs a full document reload each call (autosave→deserialize→`RequireWorld` restore; `talentPool` round-trips wholesale via `SerializationService:153,317`; `__BASHO_WORLD__` is briefly null during restore — all waits must tolerate it).

## Risks / notes for future runs

- **Fixture fragility is inherent**: the prospect graft depends on generated candidates existing (tick loop) — if the world ever produces zero candidates in ~70 days the spec fails loudly at `expect(graftedId)`. That is desired behavior (a real finding), not noise.
- **Cross-pool graft must keep single membership** — SerializationService's `idIntegrity` audit flags a candidate listed in two pools; the graft strips it from all source pools first.
- **`sendCommand` serialization**: never dispatch during `pendingTick` — commands are dropped with only a store-side `commandRejected` notice.
- **The two remaining soft spots**: `POOL-STATE` console line retained as fixture documentation; the foreign-pool regional gate means search-Prospects coverage for foreign candidates still has no e2e (would need `regionalPresence ≥ 40` — a much longer progression path; unit-level coverage exists in `entitySearchProjections.test.ts`).
